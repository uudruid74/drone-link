All engine tests are **byte-compare against output generated by the real
Python oracle** (drone_daemon.py, run 2026-11-18). Covered frames:

- TC(9B): neutral, takeoff, headless, land, calibrate+headless, sticks
  (208,68,51,153), zero-clamp (r/p/y->1, throttle stays 0), heartbeat `01 01`
- GL(21B): ids 82/85/90, neutral/takeoff/calibrate+headless/sticks
- Stick math: Python `int()` truncation semantics (e.g. -0.999 -> 88/167/126/1)
- Trajectory normalization per gear (1/2/3)
- Dead-man (stale, trajectory override, emergency-land lock)
- Rx path: auto-variant detection (first telemetry byte), photo/video ACK

## MCP surface (drone_mcp.py -> McpServer.kt)

Tool names, descriptions, input schemas, behavior, and return shapes port
VERBATIM from the `@mcp.tool()` set. The task pins the 12 tools at
`drone_mcp.py:286-400`; `status` and `video_url` (same file, lines 402-410)
are included so the surface is complete and the smoke test has a status call.

Return shapes (JSON-RPC `tools/call` -> `result.content[0].text`):
- `connect`/`disconnect` -> `{"ok":true,"status":{...}}`
- `takeoff`/`land`/`emergency_land`/`calibrate` -> `{"ok":true,"cmd":...}`
- `fly` -> `{"ok":true,"axes":[...]}` (post-set axes)
- `trajectory` -> `{"ok":true,"waypoints":n,"status":{...}}`
- `camera` -> `{"ok":true,"cam":n}`; `headless` -> `{"ok":true,"headless":b}`
- `set_gear` -> `{"ok":true,"gear":n}`; `status` -> raw status dict;
  `video_url` -> `{"ok":true,"url":...}`
- Status dict keys identical to the oracle: connected, variant
  ("TC(9B)"/"GL(21B)"), gear, headless, cam, axes, sent, rx,
  last_telemetry (null when none), trajectory_active, trajectory_index, rtsp.

Handshake: `initialize` -> protocolVersion `2025-03-26`, capabilities
`{"tools":{}}`, serverInfo `{name:"drone-ctl",version:"0.2.0"}`.
`tools/list` returns the 14 tools with verbatim descriptions/schemas.
JSON-RPC errors: -32700 parse, -32601 method not found, -32602 unknown tool,
-32000 engine unavailable.

## Deviation (intentional, documented)

- The engine binds the UDP socket lazily on the first tool that needs the
  drone, and only when the app-scoped drone network is joined
  (`network.bindSocket`). Before a join, such tools return a JSON-RPC error
  (-32000 "drone network not joined") instead of silently sending nothing —
  the Python oracle always had a plain socket to bind, so there is no
  equivalent state there. This is the honest mapping of "no joined network" in
  the app-scoped world.
- No auto-connect at service start (mirrors the daemon, which also waits for
  the first command).
- JSON is built with explicit type conversion (Android's bundled org.json does
  not auto-convert Kotlin List/Map; the Maven org.json in JVM tests does —
  divergence caught on-device, fixed, and regression-tested).
